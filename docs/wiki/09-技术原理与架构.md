# 技术原理与架构

## 组件

- Web：原生 HTML/CSS/JavaScript，负责登录、播放器、房间、聊天和管理中心。
- 服务：Node.js 22+、Express 5、Socket.IO 4，负责 REST、认证、房间状态、实时广播、上传和权限。
- 桌面：Electron 41，内置 Chromium/Node，服务器端自动启动本地服务；Windows 便携版和 NSIS 安装版都不需要外部 Node。
- Android：Java、C++ JNI、WebView 和前台服务，提供移动端客户端和受支持的手机服务器。
- 媒体：FFprobe 分析编码与时长，FFmpeg 生成缩略图和 H.264/AAC 兼容版本，HTTP Range 支持分段读取。
- 公网：Cloudflare Tunnel 或自有 HTTPS 反向代理。

## 一次播放操作

1. Electron、独立 Node 或 Android 前台服务启动 `server/index.js`，创建 Express 和 Socket.IO。
2. 客户端加载同源页面并建立 Socket.IO 连接，服务器校验密码哈希、设备、协议、房间密码和权限。
3. 房主发送播放/暂停/跳转/倍速意图；服务端更新带版本和时间的权威状态并广播。
4. 成员端依据服务器时间、RTT 和缓冲计算偏差，仅在超过阈值时校正播放器。
5. 上传通过 HTTP 流式写入，FFprobe 读取媒体信息；媒体通过 Range 请求分段读取，播放状态仍走 Socket.IO。
6. 配置和记录写入 Data 目录，锁文件保证同一目录只有一个写入实例；原子替换保护配置迁移。
7. Tunnel 将本机 HTTP、WebSocket 和媒体请求转为 HTTPS 公网入口，临时地址可能在重启后变化。

## 数据与安全

服务器保存账号、房间、媒体索引、聊天和同步状态，但只保存在房主自己的 Data 目录。密码使用哈希保存，敏感材料在 secrets 中；日志导出前必须脱敏。GitHub Pages 是静态文档，不能运行真实 WebSocket、上传或 Tunnel。
